# 忠欣 LearningOps 數據解決方案 brief

## 定位

忠欣不是單一產品或單一通路公司。公開官網呈現的是三個版圖：英語教育、品味生活、智慧倉儲。針對教育事業處的學習規劃顧問與語言策略顧問，最有力的提案不是「多做幾張報表」，而是一套能協助顧問把數據轉成校園、企業與學員決策的 LearningOps 系統。

## 核心痛點

1. 校園與企業開發高度仰賴關係經營，但拜訪優先順序、續約風險與提案時機可以由數據輔助。
2. 語言學習提案需要更具體的證據：學員基線、CEFR 目標、課程設計、評量方式與預期成果。
3. 課務執行需要即時可見：排課、出席、講師紀錄、教材使用、滿意度與測驗結果都應能預警。
4. TOEIC / TOEFL 不應只看單次報名，而應視為學習者生命週期漏斗。
5. BI 工作不只是視覺化，還包含資料來源治理、權限、安全性、指標定義與資料品質檢查。

## 建議系統

### 1. 顧問 CRM 層

追蹤學校、科系、企業、HR 聯絡人、活動紀錄、需求訪談、提案階段、專案金額、續約機率與下一步行動。

### 2. 學習旅程層

串接學員輪廓、測驗紀錄、CEFR 目標、課程報名、App 行為、出席、作業、滿意度與複測結果。

### 3. 課務營運層

追蹤開班、課表、講師配置、出席率、教材使用、異常紀錄與專案里程碑。

### 4. BI 語意層

建立 Power BI 可直接使用的標準資料視圖：

- 校園開發 pipeline dashboard
- 學習成效 dashboard
- 課務營運 dashboard
- App 啟用與留存 dashboard
- 主管 KPI dashboard

### 5. 行動建議層

把報表轉成顧問可執行的下一步：

- 本週應優先拜訪哪個校園或企業帳戶？
- 哪個班級有出席或滿意度風險？
- 哪些學員報名後還沒有啟用 App？
- 哪個企業專案適合做續約提案？
- 哪個校園分眾應收到 TOEIC / TOEFL 方案素材？

## 面試一句話

我不會只從「做報表」開始，而會先定義顧問與業務團隊真正要回答的問題，再回推 SQL 資料模型與 Power BI 語意層。好的 dashboard 應該直接告訴教育團隊：誰該被聯絡、該提什麼方案、哪個班級有風險，以及哪段學習旅程能創造下一次轉化。

## MVP 落地路徑

### Week 1：資料盤點

盤點 CRM、測驗報名、課表、出席、App 事件、問卷、電商與財務資料來源。

### Week 2：指標字典

定義共用指標：名單轉提案率、活動出席率、報名轉換率、完課率、CEFR 進步、App 啟用率、續約率、單一帳戶營收。

### Week 3：SQL views

建立帳戶 pipeline、學員旅程、課務健康度與主管 KPI 的標準資料視圖。

### Week 4：Power BI prototype

交付主管、顧問、課務與講師角色可用的 dashboard 雛形，並設計基本權限。

### Week 5-6：Pilot

選一個校園專案或企業帳戶試跑，比較 dashboard 導入前後的顧問行動、報名轉化、出席與續約機會。
