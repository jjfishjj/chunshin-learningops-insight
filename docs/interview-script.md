# 面試提案講稿

## 60 秒版本

我注意到忠欣的教育事業處同時有校園開發、企業語言專案、TOEIC / TOEFL 測驗、App 學習資源與課務執行。這代表數據分析不能只停在單一報表，而要支援顧問決策。

所以我做了一個 LearningOps Insight 原型，把帳戶開發、學員旅程、課務進度與 BI 報表整合在一起。它想回答四個問題：哪個客戶要優先拜訪、該提什麼語言學習方案、哪個班級有營運風險、哪些學員可以被引導到下一個測驗或學習資源。

技術上，我用 SQL 資料模型設計 account、learner、exam、app event、course、finance 與 data quality views，前端則做成 GitHub Pages 可展示的 dashboard。這不是宣稱知道忠欣內部資料，而是展示如果我進來，我會如何把業務需求翻成資料結構、Power BI 指標與顧問可執行的下一步。

## 面試時可強調的三個能力

1. 我能把顧問工作翻成資料問題，不只接需求做報表。
2. 我能設計 SQL / BI 語意層，讓 Power BI 報表有一致指標與權限概念。
3. 我懂語言學習場景，可以把 CEFR、測驗旅程、課程出席與學習成效接起來。

## 可以問面試官的問題

1. 目前教育事業處的 CRM、報名、課務與 App 行為資料是否已經能串接？
2. Power BI 使用者主要是主管、顧問、課務，還是講師？
3. 現在最需要自動化的報表是校園 pipeline、課務進度、學習成效，還是財務營收？
4. 對顧問團隊來說，最常見的痛點是開發新客戶、追蹤專案進度，還是續約與成效回報？

## 作品展示順序

1. 先開 `index.html` 說明三大痛點與系統定位。
2. 展示 KPI scenario selector，說明不同業務場景的主管指標。
3. 展示 dashboard 三區塊：學習旅程、課務健康度、顧問優先名單。
4. 打開 `sql/chunshin_learningops_model.sql`，說明自己不是只做視覺化，也能設計資料模型。
5. 最後用 MVP roadmap 收斂，表達可以從一個校園或企業 pilot 開始。
